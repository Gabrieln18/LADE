# LADE — project context pointer

This repository is **LADE (Lattinus Agent Development Environment)**: a governed
multi-agent environment that turns engineering tasks into reviewed artifacts for
**Lattinus Code**. It is content plus a thin profile layer — no adapters, no
generator, no build step.

The core is `.hermes/`. It is the single source of truth. Read it; do not copy it.

## Hard rules (always apply)

1. **Precedence.** `policies/` > `.hermes/SOUL.md` > `.hermes/AGENTS.md` > role
   `SOUL.md` > role manifest (`agents/<role>/AGENTS.md`) > the `task.md` instance.
   `policies/` always prevail, including over an in-session instruction.
2. **Language.** Every file in this repository is written in **English**. Delivered
   documents follow `output_language` in `task.md` (default PT-BR); code identifiers
   stay English.
3. **Contract first.** No work starts without a `task.md` instance carrying
   verifiable acceptance criteria. A task without them stays `DRAFT`.
4. **Governance paths are human-write-only.** `SOUL.md`, `AGENTS.md`, `config/`,
   `policies/`, `references/`, `templates/`, `workflows/`, `skills/`, `agents/*`,
   `evals/golden-tasks/`. Agents propose; humans merge.
5. **No agent merges.** Draft PRs only. Merge is human, gated by `CODEOWNERS`.
6. **No secrets, no invented facts.** Verify or label `unverified`.
7. **One role, one profile.** A role acts through its Hermes profile
   (`profiles/<role>/`), never by borrowing another role's tool surface.

| Human-facing overview | `README.md` |

## Working inside Lattinus Code

When a LADE role works in the Lattinus Code repository, that repository carries a
three-line `.hermes.md` pointing back to this one. The role's identity and tools
come from its profile; the domain knowledge comes from `.hermes/references/`.
